Data Flow — Page Load Sequence
1
Browser requests page
GET /index.html (or other .html)
2
Server responds
fs.readFile → streams HTML bytes with text/html MIME
3
Browser loads scripts
app.js first (globals), then page script (IIFE)
4
XHR fetch(es)
fetchJSON() calls GET /data/*.json — served as application/json
5
Transform
JS filters, sorts, aggregates the parsed JSON array in memory
6
Render to DOM
innerHTML / appendChild into pre-existing elements by id
Parallel fetch (dashboard & reports)

Both JSON files are fetched simultaneously. A loadedCount counter triggers render only after both callbacks return.

No state persistence

All state is in-memory JS variables inside each page's IIFE. Navigating to a new page resets everything — data is re-fetched on every load.

File Map
JavaScript — js/
app.js
Shared globals: fetchJSON, formatCurrency, formatDate, getStatusBadge. Loaded first on every page.
dashboard.js
KPI cards, orders-by-status counts, warehouse distribution, recent 10 orders table.
inventory.js
Product table with live search (name/SKU/id) and category dropdown filter. Highlights low-stock rows.
orders.js
Order table with clickable status filter buttons. Maintains currentFilter state.
reports.js
Monthly summary, top-5 products by revenue, summary stats. Contains 3 intentional bugs.
HTML Pages

Dashboard. Inline script for warehouse counts + dashboard.js.

Inventory list. #search-input and #category-filter wired by inventory.js.
orders.html
Orders list. Five .filter-btn buttons with data-filter attributes.

Reports. Non-functional year/status dropdowns. Three stat boxes + two data tables.
Data — data/
products.json
20 products. Fields: id, name, sku, category, price, stock, warehouse, reorderLevel. Categories: Electronics, Furniture, Office Supplies, Packaging. Warehouses: San Francisco, Tokyo, London.
orders.json
28 orders across Jan–Dec 2025. Fields: id, customerName, productId, productName, quantity, status, orderDate, total. Statuses: Pending, Shipped, Delivered, Cancelled.
Other
server.js
Node.js static server. MIME map for .html/.css/.js/.json/.png/.jpg/.ico. 404/500 error handling. Root path → index.html.
css/styles.css
All styles. Key systems: sidebar layout, KPI grid, card components, data tables, badge variants, filter buttons, low-stock row highlight, responsive 1100px breakpoint.
Intentional Bugs — js/reports.js
1
Console spam
console.log("reports debug: rendering") is placed inside renderReports(), renderMonthlySummary(), renderTopProducts(), and renderSummaryStats() — fires 4 times on every page load.
2
Non-functional filter controls
The Year and Status dropdowns (#year-filter, #report-status-filter) in the Report Filters card are fully rendered in the UI but their change event handlers are intentionally empty — selecting a value does nothing.
3
Wrong Average Order Value calculation
In renderSummaryStats(), the Avg Order Value is computed as totalRevenue / products.length (dividing by 20 products) instead of totalRevenue / totalOrders — producing an inflated and incorrect value.
